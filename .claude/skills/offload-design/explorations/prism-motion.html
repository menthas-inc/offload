Prism motion

Three treatments at true device size, with the prism textures you picked. Everything that moves below moves by transform only, on an already-rasterized texture, which is the whole reason this is affordable: the marketing site pays ~96ms of raster a frame because its washes drift inside a turbulence filter, and there is no filter here to re-run. In React Native each of these is an Animated value with useNativeDriver: true, so it runs on the UI thread and never touches JS.

Speed Real time is what ships. The previews only speed the clock up so you can see the path.

  • The arrival nudge runs on --duration-mark, the 1400ms the change mark already uses, so a row arriving and the band shifting are one gesture rather than two effects that happen to coincide. That is the argument for 3 over anything perpetual: it is the only option that carries meaning, and it is the same sentence the moss ground is already saying.
  • The parallax factor is deliberately small. The band is 20% wider than the screen, so there is real headroom, and the temptation is to use it: at anything above about 0.08 of scroll distance the field starts to feel like a separate object sliding behind a window rather than the page having depth.
  • Perpetual drift on the plate is the weakest case for it, and the third frame is the strong one. Most of the band is behind an opaque input and three tab labels, so a 4px drift is spending battery on pixels nobody can see. The same 4px on the gate's bloom is across the whole top of the screen.
  • Reduced motion cuts all of it, including the parallax, which the standing rule requires: a shortened animation is still an animation. The band simply sits where it is.
  • One thing to decide if you take 2: whether the drift pauses while the list is scrolling. It costs nothing to leave running, since both are native transforms, but two motions at once on the same layer is the sort of thing that reads as drift rather than as parallax.
