Thread widgets, three kinds, three options each

A thread shows only the widgets its contents justify: a trip earns a map, a build earns a timeline, a shopping thread earns a file grid. Each option below is drawn at the width of the thread page, under a real section header, so you can judge it in place.

On the map. I cannot generate imagery, so the map surfaces below are placeholders with real pin placement and real list behaviour. A shipped version needs either a tile provider or a vector map drawn from actual coordinates, which I can do properly once we pick a layout.

1. Map

The question is how much room the map earns. It is the most attention-grabbing thing on the page, and for most threads the list of places is what you actually act on.

1a. Map on top

A 150px map above the numbered list, pins matching the numbers. Familiar, and the pairing means you can read the list and glance up. Moss pin marks a place someone else suggested, blue one that needs a decision.

2. Timeline

Granularity follows the thread: a trip spans days, a moving day spans hours. All three switch between the two, the difference is the shape.

2a. Vertical spine, grouped by day

Dates as small headers, entries hanging off one spine. Reads like the rest of offload, handles any span, and hour detail simply appears in the time slot. Dot colour marks done, next up, or waiting.

3. Files

Filter chips are the same in all three: file type first, then tags offload derived from the contents (moss, because you did not type them). The variable is how the files themselves are presented.

3a. Three-up grid

Thumbnails first, names small underneath. Right when most things are images, which is usually true of a shopping or renovation thread. Poor for PDFs and links, which all look alike.

My read. 1b for the map, because a sentence plus a thumbnail beats a map you cannot really use at 150px, and the full map is one tap away; 1a if you want the map to be the thread's identity. 2a for the timeline, since it is the only one that handles both granularities and any span without changing shape. 3a for files, with 3c as the state you switch to when a tag chip is selected, which gets you the grid by default and the clever grouping on demand.

Also worth deciding: whether widgets are chosen by offload from the contents, or pinned by you. My instinct is offload proposes, you can dismiss, and a dismissed widget never comes back for that thread.
