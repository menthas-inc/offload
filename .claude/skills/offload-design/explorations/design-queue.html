Design queue

Fifteen things the codebase asked this design system for and has not received. Each one is new surface rather than a correction: the app already has an answer for all fifteen, invented while building, and every one is logged in decisions.md with its reasoning. This exploration shows what the app does today, drawn at real size in the system's own tokens, and two or three ways to fold each one in. Pick per item and I will take them into the kits and the components.

All fifteen, with my recommendation

read the part for the options and the costs
 OwedSurfacesMy recommendation
1The memories sectionweb, phonesRows, not chips. A memory is a sentence up to 200 characters and a chip truncates it to a window you have to click to read. Chips stay only if you want the compact look, in which case Chip should own the ellipsis.
2A memory, openwebAs built if chips stay, governed as a MemoryEditor with the chip as its closed state. If rows win, the editor is just the row expanding.
3The archived toggle and an archived rowallKeep the pane tool, replace the opacity. Archived rows go secondary ink with a hollow tile and a relabelled date, and lose every action except putting them back.
4A finished task, in placeallAs built, opacity removed. Tertiary ink and a hairline strike. Collapsing the done pile solves a problem threads do not have yet.
5Row tools drawn as conditionalallAbsent, not disabled. Two rows showing different tools is honest; a control that is drawn and refused teaches a rule that is not true.
6What the pane head holdswebBuild the More menu. The kit already draws the ellipsis, the head is at its width, and rename, add memory, archived and Leave all want to live in it.
7The swipe and the long pressphonesKeep both gestures and govern the action sheet. It is the only option where a swipe means the same thing in every list in the product.
8Glyph, the React Native icon contractphonesA second contract, Glyph.d.ts beside Icon.d.ts, same 80 slugs, color in place of inheritance. The lint already treats them as different components.
9Filter or group in a widgetweb, phonesGroups only, and the real work is a sub-heading rank between SectionHeader and body, which the system does not have and several screens want.
10A failed turn, and a half-finished oneweb, phonesTwo treatments, not one. A failure needs finding, so it takes the system's tinted inline error; a partial turn already has a reply saying what happened, so a line under it is enough.
11The reply that links to its threadsallPills, as built, with one refinement: when a turn touched exactly one thread, the pill is the only mention and the sentence drops the name.
12A theme switch and a type-size controlallNamed rows in the nav, and a Settings page too. Both read the same stored value. An unlabelled accessibility control is the defect worth fixing first.
13Leaving versus deleting a shared threadall unbuiltTwo words. Leave for a shared thread, Delete for a private one, the confirmation names the other members, and the last member gets the warning and the clay.
14A row before its thread is settledall unbuiltOne moss word, "filing", in the thread's own slot. The only option that reads as progress rather than as a correction or a bug. If the sorter is fast enough, showing Miscellaneous costs nothing.
15What the share sheet does not sayallThe longer paragraph, and the permission line comes out. Decided against my recommendation and applied: the sheet spends its one sentence on co-ownership, and the Ending things page carries the account-deletion half.

What this changes in the system

if every recommendation is taken
  • Three new components: a RowActionSheet for the phones, a MemoryEditor or memory row for the thread page, and a Glyph contract for React Native.
  • Two new ranks in the type and heading system: a sub-heading between SectionHeader and body, and a governed treatment for a finished or archived row that does not use opacity.
  • One vocabulary addition: Leave, alongside Delete, with the rule for which applies.
  • One pattern the system does not have: a per-row progress word, if item 14 goes that way. Worth deciding deliberately, since today the system has one spinner and nothing else.
  • Four kit screens gain surface: the thread page on three clients, the composer on web and the phones, the share sheet on three clients, and the sidebar foot on web.
