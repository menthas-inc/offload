# 009 The phones, implementation spec

> How. The catalogue is in `inventory.md`, the product statement and the 51 criteria are in
> `feature-spec.md`. This is the shape of the code and the six or seven places it is easy to get
> wrong.

## Shape

One new package, one extended API layer, two screen trees, and one piece of genuinely novel
interaction.

```
packages/widgets/            new. the shared rule, imported by all four clients
apps/mobile/lib/             api.ts extended, threads.ts and dump.ts ported, log.ts new
apps/mobile/app/(tabs)/      today, threads, memories
apps/mobile/app/threads/[id] the thread screen
apps/mobile/components/
  screens/*.ios.tsx          one file per platform, the convention already in use
  screens/*.android.tsx
  shell/Plate.tsx            composer, folded header, tab bar
  shell/Conversation.tsx     the sheet, and the fold
```

**Nothing about the server changes.** Every endpoint the phones need exists and is listed in
`inventory.md`. If this spec seems to want a new one, that is the signal to stop and check.

## What the app already gets right, and must not lose

Three things are already solved in `apps/mobile` and are easy to undo by accident:

- **Platform split by file suffix.** `Today.ios.tsx` and `Today.android.tsx` already exist. The
  two kits are different designs, not one skinned, so this is the mechanism for AC-2 rather than
  a `Platform.OS` ternary inside one component.
- **Tokens, two ways.** NativeWind classes from the generated Tailwind preset for everything that
  takes a class, and `lib/colors.ts` reading `@offload/tokens` for the props that take a colour
  value, like an SVG stroke. Both are generated by `pnpm tokens`. A literal is what OFF-7 forbids
  and the second mechanism exists so nobody needs one.
- **The request layer.** `lib/api.ts` awaits the cookie out of secure storage rather than
  spreading a promise, bounds every call with `within()`, and **sets `content-type` only when
  there is a body**. That last one is the rule the web client got wrong last week, shipping two
  deletes that silently did nothing. Extend this file. Do not write a second one.

## The shared widgets package

`packages/widgets`, holding `WIDGET_KINDS`, `EARNS`, `sinkDone`, `widgetsFor`, `groupBy`,
`readPreference`, **and `parseTag` and `dimensionsIn`**.

Pure TypeScript, no React, no DOM, no React Native.

**The last two are not optional and their absence was a real hole in the first draft of this
page.** `groupBy` calls `parseTag`, and the two sides get it from different places: web keeps a
private copy at `apps/web/src/lib/widgets.ts:33`, the server imports it from
`apps/core-api/src/threads/tags.ts:32`, which also owns `dimensionsIn`. Extracting only the six
functions named above would give the package its own third `parseTag` sitting beside the server's,
which is decision 8's problem relocated rather than removed. So both move, and
`apps/core-api/src/threads/tags.ts` imports them back for `normaliseTags`, which is write-time
validation and stays server-side.

**Three things it needs to be a package rather than a folder**, modelled on `packages/tokens`
because that is the one that works: a `package.json` with an `exports` map pointing at `dist/`, a
build, and a **`prepare` script**. *`packages/tokens` has `prepare` for a reason this repo paid
for: `dist/` is gitignored, only CI ran the build, and every EAS build failed. A generated
artifact must be generated by `install`, not by a step someone remembers. Neither `next.config.mjs`
nor Metro is configured to transpile raw TypeScript from a workspace package, and both only work
with `@offload/tokens` today because it ships compiled JavaScript.*

### What the migration actually costs

"Both suites run unchanged" was wrong, and the honest version is small but not nothing:

- **`apps/web/test/widgets.test.ts`** builds its fixtures with `place: {...}`. The shared
  `Sortable` takes the server's shape, `placeId`, because that is what the API returns, so those
  fixtures change and the web maps at the edge.
- **`apps/core-api/test/widgets.test.ts`** imports `dimensionsIn` from `../src/threads/tags.js`;
  that import moves. Roughly a third of that file is a database-backed route test asserting query
  count, which exercises the route rather than the moved module and does not move with it.

## The API layer

`lib/threads.ts` and `lib/dump.ts` port almost verbatim: they are `fetch` and types, and the only
DOM in either is `EventSource`.

**Every bodyless call uses the credentials-only init**, which `api.ts` already does correctly by
construction. The web has `send` and `json` as two constants and the bug was picking the wrong
one; here there is one `request()` and it decides from the presence of a body, so the mistake is
not available.

### The stream

`EventSource` is not in the React Native runtime, and AC-23 says the phones ship without it.

`awaitAnswer` becomes a poll of `fetchAnswer` on the phones. That is not a downgrade to build
around: `dump.ts` already documents the fetch path as "the one that cannot fail to arrive" and the
stream as an optimisation over polling.

**With numbers, because "bounded" is not a specification.** One second while a turn is live, since
that is what the web used before `pg_notify`, backing off to five after twenty misses, and
stopping entirely on `answered`, `partial` or `failed`. It stops when the app backgrounds rather
than running behind a lock screen, and **returning to the foreground asks immediately** rather
than waiting for the next tick, or every backgrounded turn pays an extra interval before 👀
becomes Done.

*Worth stating because this is genuinely new request volume. Nothing polls this route today: web
calls it once per stream reconnect, and the server is `pg_notify`-driven with a fifteen second
keep-alive. There is no rate limiter on the route to catch an interval set too tight.*

*When a polyfill arrives, close the connection on `AppState` leaving active rather than relying on
TCP teardown. A phone drops sockets far less predictably than a browser tab, and the server's
per-connection subscription lives until `request.raw.on("close")` fires.*

## Logging, and why it is a module rather than a rule

`AC-33a`. The server states OFF-1 in a comment and then enforces it with pino's redact list and
narrowed serializers, because this repo already learned that an intention is not a control.

`lib/log.ts` is the phone equivalent: ids and outcomes only, never a title, a body, a dump, a
thread name or a memory. Nothing outside it calls `console.*`, and **no crash reporter is added
until it exists**, because a crash SDK's default breadcrumbs capture console output and network
activity, and by then the leak is a vendor's problem to unpick.

React Native makes this harder than the browser in three specific ways worth naming: an unhandled
rejection prints the whole error object, the dev red box renders it, and a fetch failure's message
can carry a request body. The module's job is that none of those three ever holds content.

## Session storage

`AC-32a`. `lib/auth.ts` passes `SecureStore` straight into `expoClient`, and neither that call nor
`@better-auth/expo`'s `setItemAsync` supplies options. `expo-secure-store` then defaults to
`WHEN_UNLOCKED`, which is the accessibility class that **is** migrated when a device restores from
an encrypted backup, and sessions live thirty days.

So the storage handed to the plugin is a thin wrapper pinning
`AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY` on write. `expoClient` only ever calls `setItemAsync(key,
value)`, so a wrapper injecting the option is straightforward and reads are untouched.

**That fixes iOS and says nothing about Android.** `keychainAccessible` is marked `@platform ios`
in `expo-secure-store`'s own types. Android uses the Keystore under a different model, and this
page does not assert what its backup behaviour is, because nobody has checked. **Verify it the way
the app loads it before claiming anything**, which is this repo's own rule, and write the answer
here.

**Existing sessions keep the old class until something rewrites them.** Accessibility is applied
at write time and there is no re-encrypt on read, so an account that signed in before this ships
is not covered until its cookie happens to be rewritten, which may not happen inside thirty days.
First launch after the upgrade reads the value and writes it straight back under the new option.

**Signing out resets the tree**, not just the two keys. Once the phones hold threads, a second
account on a shared device must not get a frame of the first one's thread names.

## The shell

`expo-router`, which is already the router. `app/(tabs)/` for the three, everything else a stack
push, so AC-4's per-platform transition is the navigator's rather than something hand-animated.

**The plate** is one raised surface holding, in order, the folded conversation header, the
composer and the tab bar, with `--radius-xl` top corners. It is a component rather than three
siblings because the keyboard moves all of it together and the fold changes its height.

| Screen | Composer | Tabs |
| --- | --- | --- |
| The three tabs | yes | yes |
| A thread | yes, "Add to this" | no |
| Conversation raised | inside the sheet | no |

*The middle row is the divergence: the kit sets `showComposer` false inside a thread and this
keeps it. It ships with its `decisions.md` entry in the same commit, not after.*

## The keyboard

The single largest risk, and the one the mock cannot express.

**It is not installed, and adding it is a native step, not an npm one.** The app runs on a custom
dev client, so the dependency needs `expo run:android` or an EAS dev-client build before any
device testing happens; a Metro reload will not pick it up. Its peer range against RN 0.86 and
Reanimated 4.5.1 is checked before committing to it, not after.

**`react-native-keyboard-controller`, not `KeyboardAvoidingView`.** The stock component's
`height`/`padding` behaviours are the ones that fail on Android exactly when an app is edge to
edge, which this app is, and `adjustResize` is ignored for the same reason. This repo has already
paid for that once on the waitlist form. The library gives a keyboard height that is animated in
step with the system, on both platforms, which is what the plate needs to ride.

**The tab bar hides while typing** (AC-29c) rather than riding up glued beneath the field. A
thread screen has no tab bar and sidesteps it; the tabs do not.

Every screen with a field is checked on a device before its task is closed, Android first.

## The conversation, and the fold

The novel piece. Built on `react-native-reanimated`, which is already a dependency, rather than a
bottom-sheet library.

*A sheet library gives a sheet: open, closed, snap points, a backdrop. The fold is none of those.
It is a sheet that collapses into a header inside a different container while keeping its state,
and wrapping a library to get that is reliably worse than owning about eighty lines of animated
height. Reconsider if a second sheet appears in the product.*

**`GestureHandlerRootView` is missing and every swipe depends on it.**
`react-native-gesture-handler` is a declared dependency with no usage anywhere in `app/` or
`components/`, and `app/_layout.tsx` does not wrap the tree. Without it, Android swipes silently
do not register or fight the navigator, which is the classic version of this bug. It goes in the
root layout before any swipe row ships.

Three states, one shared value: **raised** over the screen with its own composer, **folded** to a
header above the main composer, **closed**. The turns and the draft live above all three, so
folding cannot lose them (AC-24), and **a live Undo toast survives the fold**, because an eight
second window that vanishes when somebody tidies the screen was not eight seconds.

## Rows and gestures

`SwipeRow` reveals a delete and nothing else: the `trash-2` glyph and the `--clay-600` ground are
inside the component and only the label is a prop. So:

- **Thread rows** swipe to delete, which is what the component is. Straight to a toast, no
  confirmation (decision 7), and the toast says whether the thread was deleted or left (AC-9).
- **The default thread** does not swipe to a delete. It answers instead, with a plain no-action
  `Toast`, because `Toast` carries one action and the Undo needs it. `isDefault` comes from the
  server, which `GET /v1/threads` already returns.
- **Content rows** are blocked on the fifth open design question. **Nothing improvised here**: a
  swipe labelled "Archive" showing a trash can is what happens if somebody builds it anyway.

## Testing

`apps/mobile`'s `test` script is `echo "no mobile tests yet"`. That is defensible for a gate made
of screens and indefensible for the polling loop, the ported API layer and the ordering in
AC-31a to AC-31c.

**`lib/threads.ts`, `lib/dump.ts` and the poll are plain TypeScript with no React Native in them**,
so they run under the same `vitest` setup `core-api` and `web` already use, with no device and no
renderer. Everything that genuinely needs a device stays a device check; everything that does not
stops pretending it does.

## Volume and access

No new tables and no new queries. The phone reads exactly what web reads:

| | |
| --- | --- |
| My threads | one `GET /v1/threads`, all groups, as web |
| A thread | the five-query bundle, then a page of content on a cursor |
| Paging | server-side and cursor-based, inherited from 005's AC-6. `See all` does not fetch a thread to count it. |
| Caching | in memory for the session. **Nothing about a thread is written to disk**, and if that ever changes it uses the same secure boundary the session does and is cleared on sign-out. |

## Edge cases

| | |
| --- | --- |
| A thread is swiped away while a turn is filing into it | The tool call finds it gone and gets the one generic refusal, so the turn is partial. offload does not explain it. Both undoing the delete and finishing the turn work, either order (AC-31a to AC-31c). |
| The app backgrounds mid-turn | The poll stops; the answer is still there on return, because the server stored the dump before anything else. |
| The app switcher | The root layout covers the screen when `AppState` leaves active, so the OS snapshot is not a thread's contents (AC-33b). |
| A deep link to a thread | The screen renders nothing from the route param and waits for the server. A refusal is identical whether the thread is missing or somebody else's (AC-34a). |
| Reduced motion | Movement is removed rather than shortened, once, in a shared animation config rather than per component. |
| No network | The dump fails to send and says so in one clause with a way to try again. It never claims to have filed anything. |

## Constitution check

| | |
| --- | --- |
| **OFF-1** | `lib/log.ts` is the only thing that logs, ids and outcomes only. No crash reporter before it exists. The app switcher is covered. |
| **OFF-3** | Every authorization decision is the server's. The phone draws a control when the server says so, `isDefault` and `canDelete` included, and the server refuses regardless. |
| **OFF-4** | Nothing new reaches a model. The phones send dumps to the same endpoint. |
| **OFF-6** | Undo is eight seconds and survives the fold. Deleting a thread confirms on web and does not on a phone, which is decision 7 and is recorded. |
| **OFF-7** | Tokens through NativeWind and `lib/colors.ts`. Every divergence from a kit gets an entry with a filled Design system impact. |
| **OFF-8** | No change: the phones render what the server already bounds. |
| **SEC-1** | The session is device-only and never leaves secure storage except as a header. |
| **DATA-1** | No local persistence. Nothing to purge on the device. |
